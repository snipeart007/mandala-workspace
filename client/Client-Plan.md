# Desktop Client Setup Plan

## 1. Architecture & Tech Stack
- **Framework:** Wails (v2) with Go backend and React frontend.
- **Frontend Stack:** React, Material UI (MUI) for component styling, Zustand for state management, React Router for navigation.
- **Backend Stack:** Go, gRPC Client (via generated protobufs), `os/exec` for external file handling.
- **Communication:** Wails IPC for synchronous calls. gRPC streams (for file transfer) are handled entirely within the Go backend to avoid passing large data blobs over the Wails IPC bridge.

## 2. Wails Backend Modules (Bottom-Up Approach)
We will divide the Go backend into manageable, single-responsibility modules before writing the main application logic.

### 2.1. Helper Modules
- `pkg/config`: Manages client-side configuration (server address, TLS settings, local temporary download directory).
- `pkg/logger`: Centralized logging for the desktop client, wrapping standard `log` or a structured logger like `zap`.
- `pkg/sysutils`: Cross-platform utilities for OS interactions.
  - `OpenFile(path string)`: Uses `open` (macOS), `start` (Windows), or `xdg-open` (Linux) to launch a file in its default native application.
  - `GetTempDir() string`: Resolves a safe temporary directory for downloaded files.
- `pkg/auth`: Manages secure local storage of the PASETO token and device private key (Ed25519) required for the challenge-response flow.

### 2.2. gRPC Client Integration (`pkg/grpcclient`)
This module encapsulates the connection to the `mandala-workspace` server.
- `ConnectionManager`: Initializes the `grpc.ClientConn` with TLS credentials.
- `AuthInterceptor`: A gRPC Unary and Stream interceptor that automatically injects the stored PASETO token into the `authorization` metadata header for every request (except Login/Register).

### 2.3. Wails Application Bindings (`app/services`)
These structs are bound to Wails and expose methods directly to the React frontend. They act as adapters over the gRPC clients.
- `AuthService`:
  - `Login(userId, deviceId)`: Handles the challenge-response flow transparently (calls `LoginUser`, signs the challenge with the local key, calls `VerifyLoginSignature`, and stores the resulting token).
  - `RegisterDevice(...)`: Handles the initial device registration and keypair generation.
- `WorkspaceService`:
  - `ListFolder(folderId)`: Returns a mapped `ListFolderResponse`.
  - `CreateFolder(...)`, `MoveFolder(...)`, `DeleteFolder(...)`.
- `FileService`:
  - `UploadFile(localFilePath string, folderId uint64)`: **Crucial Optimization:** The frontend passes a *local file path* obtained via native file dialogs. The Go backend opens this file directly and streams chunks to the gRPC `UploadFile` endpoint, bypassing the Wails IPC for file content.
  - `DownloadFileToTemp(fileId, versionId)`: The Go backend streams the file from gRPC to a local temporary file, then returns the absolute path of the temp file to the frontend.
  - `ListVersions(fileId)`.
- `AdminService`:
  - Exposes user creation, device revocation, and system management functions.

## 3. Frontend Setup & Architecture
The React application will be initialized using Vite for speed and modern build tooling.

### 3.1. Directory Structure
```
frontend/
├── src/
│   ├── api/          # Wails bindings (auto-generated by wails generate module)
│   ├── assets/       # Icons, global styles
│   ├── components/   # Reusable MUI components (FileIcon, Dialogs, DataGrid)
│   ├── features/     # Feature-based modules
│   │   ├── auth/     # Login pages, setup wizards
│   │   ├── explorer/ # The main file system UI
│   │   └── admin/    # User/device management
│   ├── store/        # Zustand stores (useAuthStore, useWorkspaceStore)
│   ├── utils/        # Formatting, date parsing
│   ├── App.tsx       # Main router setup
│   └── main.tsx      # Entry point, MUI ThemeProvider
```

### 3.2. State Management (Zustand)
- `useAuthStore`: Manages current user info, authentication state, and token validity.
- `useWorkspaceStore`: Manages the current folder ID, breadcrumb trail history, and caches folder contents to ensure a snappy UI during navigation.

## 4. UI Components & Pages

### 4.1. Authentication & Setup
- **Admin Setup Page (First Run):** A wizard to configure the backend server address, test connectivity, and perform initial admin setup via `SetupAdmin`. This flow generates the first admin user, registers the device, and initializes the secure local keyring.
- **Login Page:** Simple UI requesting User ID/Email. The heavy lifting (challenge-response signing) happens silently in the Go backend using the unlocked keyring.

### 4.2. Workspace Browser (File System UI)
- **Layout:** A split-pane layout. A left sidebar for quick access (Root, Recent). A main area for the folder contents.
- **Breadcrumb Navigation:** MUI Breadcrumbs at the top for navigating back up the directory hierarchy.
- **DataGrid / List View:** A sortable list (using MUI DataGrid or a custom List) showing Name, Type, Size, Last Modified, and Context Actions.
- **Toolbar:** Context-sensitive actions (New Folder, Upload File, Refresh).
- **Upload Flow:** Clicking "Upload" triggers Wails `runtime.OpenFileDialog`. The selected path is then sent to `FileService.UploadFile`.

### 4.3. User & Permissions Management (Admin)
- **User Management View:** A table showing all users, their roles, and their registered devices.
- **Permissions Modal:** When right-clicking a folder -> "Manage Permissions", a dialog opens displaying the current bitmask permissions for different users, with toggles to update them.

## 5. External File Handling Strategy (Direct Opening)
To support opening files seamlessly in their native applications (e.g., PDFs in Acrobat, Docs in Word):
1. The user double-clicks a file or selects "Open in Native App" in the UI.
2. React calls `FileService.DownloadFileToTemp(fileId, versionId)`.
3. The Go backend securely streams the file from the gRPC server to a scoped local file in `os.TempDir()`.
4. The Go backend returns the local file path to React.
5. React calls `sysutils.OpenFile(localPath)` (exposed via Wails).
6. The Go backend uses `os/exec` to launch the default OS application for that file type.
7. **Modifications (Manual Upload):** As configured, the UI will provide an "Upload New Version" button in the file's context menu. If a user edits the file externally, they must save it, then manually trigger the upload flow to push the new version to the server.

## 6. Implementation Phases
- **Phase 1: Backend Scaffolding.**
  - **1.1. Project Initialization:** Initialize the Wails v2 project with a React-TS template. Establish the Go project structure (`pkg/`, `internal/`, `app/`). Ensure the `SetupAdmin` RPC is available in the generated gRPC client for the initial configuration.
  - **1.2. Logger & Config Modules:** Implement structured logging and a configuration manager to handle server endpoints and local preferences.
  - **1.3. Sysutils Module:** Implement cross-platform native file opening (`OpenFile`) and system-specific temporary directory resolution.
  - **1.4. Secure Identity Management (Auth Module):**
    - Implement a local "Keyring" storage system for the device's private Ed25519 key and PASETO session tokens.
    - **Encryption Strategy:** All sensitive identity data must be encrypted at rest using a strong symmetric algorithm (e.g., AES-256-GCM). The encryption key is derived from a user-provided master password using a high-cost KDF (Argon2id).
    - **Security Mandate:** Keys are never stored in plaintext and remain in memory only during an active session. The program must require the master password to unlock the keyring upon startup or after a period of inactivity.
  - **1.5. gRPC Client Core:** Integrate the shared proto sources from the root `proto/` directory. Generated Go code must be scoped locally to the `client/` module to maintain strict separation from the server's implementation. Implement a `ConnectionManager` with a PASETO-injecting `AuthInterceptor`.
- **Phase 2: Service Bindings.** Implement the Wails structs wrapping the gRPC methods. Focus heavily on implementing the local-file-to-gRPC-stream translation logic for efficient uploads/downloads.
- **Phase 3: Frontend Scaffolding.** Setup Vite, React, MUI ThemeProvider, and Zustand stores. Build the initial setup wizard and login flow.
- **Phase 4: Workspace Explorer.** Build the main file system interface, breadcrumbs, DataGrid, and connect it to the `WorkspaceService`.
- **Phase 5: File Operations.** Implement upload, download, and the "Open in External App" execution flow.
- **Phase 6: Admin & Permissions.** Build the user management and folder permission modification UIs.
